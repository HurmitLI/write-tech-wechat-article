## 1. 逐题问题库

一次只问一个问题。根据用户已经给出的答案跳过重复项。

### 核心收获

问题示例：这篇文章最核心的阅读收获是什么？

选项应围绕不同结论设计，例如理解新架构、判断产品优势、决定是否采用。不要用不同措辞重复同一个意思。

### 主打优势

问题示例：你认为最值得重点展开的优势是哪一个？

选项应对应不同竞争维度，例如模块可替换、部署自主、上下文可控、工具生态成熟。

### 读者深度

问题示例：你希望读者理解到哪个程度？

常用层级：普通用户能理解、产品经理能比较、技术负责人能做选型。

### 正文入口

问题示例：你更想从哪件事进入正文？

常用入口：已有成熟竞品为何还要做、一次真实使用困惑、一个反常识数据、一项设计冲突。

### 文章态度

问题示例：你希望文章对研究对象保持什么态度？

常用选项：明确看好但交代代价、中性比较、重点质疑承诺与落地差距。

### 下一交付

问题示例：接下来想先看到哪部分？

选项：完整详细提纲、开头试写、直接完整成稿。

## 2. 标题收敛

先确认点击动机，再压缩语言。

可用的标题动力包括：

- 已有成熟方案，为什么还要再做一个。
- 一个被大多数讨论忽略的差异。
- 一项新设计会改变谁的选择。
- 用户以为在比较模型，其实还漏看了什么。

拒绝没有信息量的套词。用户否定标题时，询问具体不喜欢的是词语、长度、结论暴露、语气还是点击动力，然后只改对应变量。

## 3. 提纲模板

### 开场

- 展示已有产品已经解决了什么。
- 提出目标产品仍然出现的反常识问题。
- 给出作者研究动作和暂时性判断，不一次讲完结论。

### 第一章 先讲清是什么

- 用一句通俗定义建立概念。
- 说明它在整个系统中的位置。
- 给一个任务流程或使用场景。
- 解释为什么同一模型在不同系统里表现不同。

### 第二章 建立比较坐标

- 说明三家都能完成什么。
- 选出共同维度。
- 用表格或一张图先给读者全景。
- 指出真正的分歧落在哪里。

### 第三章 展开核心优势

- 按功能模块或产品问题拆成三至四节。
- 每节完成“现状—差异—企业意义—代价”。
- 使用同一节内三方对照，不按厂商分别写说明书。

### 第四章 适用场景与判断

- 给出适合成熟产品的团队。
- 给出适合开放架构的团队。
- 说明集成、安全、维护和版本兼容代价。
- 回答标题中的问题。

| 可观测性 |  |  |  |  |

每个单元格只写可核验事实或明确推断。正文不必展示全部矩阵，但所有比较必须来自同一坐标系。

## 5. 段落推进

用以下顺序组织重要段落：

1. 给出具体事实或场景。
2. 解释这一事实背后的机制。
3. 说明它改变了谁的选择。
4. 补上限制、反例或代价。

连续三段都只在解释同一概念时，删除重复段或加入新的事实、案例和边界。
