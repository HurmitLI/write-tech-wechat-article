## 1. 默认配色

没有参考稿或品牌规范时使用以下编辑风格：

| 用途 | 颜色 |
|---|---|
| 正文深灰 | `#2E2E31` |
| 辅助文字 | `#6B6B70` |
| 烧橙主强调 | `#C9633F` |
| 低饱和蓝 | `#5C6FA3` |
| 橙色浅底 | `#F6E8E0` |
| 引用浅灰底 | `#F3F1EE` |
| 页面米白 | `#FAF8F4` |

蓝色负责英文产品名、技术名、链接和结构性信息。橙色负责一级标题、关键结论和少量行动词。正文保持深灰，避免整页彩色。

## 2. 字号与留白

公众号内容区默认最大宽度 677px。

| 元素 | 建议值 |
|---|---|
| 主标题 | 30–34px，行高 1.25–1.35 |
| 副标题 | 18–21px，行高 1.55–1.7 |
| 正文 | 16–17px，行高 1.85–2.0 |
| 一级标题 | 24–26px，上间距 50–60px |
| 二级标题 | 20–22px，上间距 38–46px |
| 资料与图注 | 13–14px，行高 1.65–1.8 |
| 图片上下间距 | 32–40px |

段落默认每段一个主要意思。移动端阅读时，避免连续出现超过六行的高密度长段。

## 3. 内容着色

默认蓝色标注这些类型：

- 产品与公司：DeepSeek、Codex、Claude Code、OpenAI、Anthropic。
- 架构与能力：Harness、Agent、Plugin、MCP、CLI、SDK、Shell、Diff、Context。
- 本文反复比较的自定义专名。

第一次出现时可使用“公司 + 产品”全称，后续保持统一。不要出现 `Deepseek`、`ClaudeCode`、`claudecode`、`codex` 等非正式写法，引用原文除外。

标题可以使用橙蓝组合；正文中的名称以蓝色为主。普通英语、数字、日期和网址不需要逐个着色。

## 4. 色块与引用

### 关键短语

使用橙字浅橙底、粗体、小圆角。每屏最多一至两个，避免把整句话做成荧光笔。

```html
<span style="color:#C9633F;background:#F6E8E0;font-weight:700;padding:2px 6px;border-radius:5px;">关键短语</span>
```

### 核心公式或判断

使用浅灰背景、橙色左边框。公式可以居中，作者判断保持左对齐。

```html
<blockquote style="margin:30px 0;padding:22px 25px;background:#F3F1EE;border-left:5px solid #C9633F;border-radius:8px;font-size:19px;line-height:1.75;">核心判断</blockquote>
```

## 5. 正文配图

每张图只解释一段难以用文字快速理解的关系。

适合配图的内容：

- 一个模块在系统中的位置。
- 三个产品在同一维度上的差异。
- 一个企业工作流的前后变化。
- 多模块替换、组合或依赖关系。
- 三步以上的执行与状态变化。

精确图使用米白背景、黑灰线条、蓝色结构信息、橙色结论或风险。保持几何关系准确，最多五个横向节点。不要用生成式图片承担精确文字和数据。

## 6. 封面

默认生成约 2.35:1 的公众号横版封面。标题放在左侧或中间安全区，视觉主体放另一侧，四周留足裁切空间。

优先使用“模块、接口、卡片、插槽、连接关系”等产品设计隐喻。缩略图只保留主标题，不堆副标题、日期、作者和标签。生成后逐字检查中文、英文和大小写；文字错误时定向重做。

避免人物、机器人脸、芯片、代码雨、霓虹和复杂3D，除非它们确实服务于主题。
