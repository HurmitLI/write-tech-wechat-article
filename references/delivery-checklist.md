# 发布前检查清单

## 目录

1. 观点与结构
2. 事实与来源
3. 语言
4. 视觉
5. 公众号交付

## 1. 观点与结构

- [ ] 一句话能说明文章希望读者带走什么。
- [ ] 标题提出的问题在结尾得到明确回答。
- [ ] 开头没有用泛行业背景拖延进入主题。
- [ ] 每章承担不同任务，每节只有一个中心句。
- [ ] 比较对象使用同一组维度。
- [ ] 优势、代价和适用团队都被说明。
- [ ] 作者立场明确，但没有把偏好冒充事实。

## 2. 事实与来源

- [ ] 版本、日期、价格、开放范围和许可为最新信息。
- [ ] 核心事实来自官方页面、文档、仓库、许可证或论文。
- [ ] “开源”写明具体开源部分，不笼统概括整个产品。
- [ ] 直接引语逐字核验并控制长度。
- [ ] 推断使用“这意味着”“可以理解为”等语言标明。
- [ ] 资料列表中的链接可以打开并直接支持对应说法。
- [ ] 标明资料检索截止日期。

## 3. 语言

- [ ] 开头和结尾没有模板化行业口号。
- [ ] 没有连续重复同一观点来扩充字数。
- [ ] 技术概念都落到产品或企业影响。
- [ ] 长短句与段落长度有变化。
- [ ] 正文清除了冒号、破折号和机械翻案句。
- [ ] 产品名、公司名、大小写与空格统一。

## 4. 视觉

- [ ] 一级标题、二级标题、正文和资料区层级清晰。
- [ ] 英文产品名和技术名按规则着色。
- [ ] 关键色块数量克制，没有满屏强调。
- [ ] 每张正文图都承担明确解释任务。
- [ ] 图片中的文字、箭头、数量和关系准确。
- [ ] 图片风格、比例、配色和圆角统一。
- [ ] 封面缩小后仍能读清标题，安全区没有被裁切。

## 5. 公众号交付

- [ ] HTML正文样式全部内联。
- [ ] 复制按钮与说明位于正文容器之外。
- [ ] 图片在本地打开时完整显示。
- [ ] 链接、引用、编号、列表和图注没有丢失。
- [ ] 已运行英文名称与颜色审计并得到 `PASS`。
- [ ] 已在窄屏宽度预览一次。
- [ ] 交付说明写清打开、复制、粘贴和公众号二次清理风险。
